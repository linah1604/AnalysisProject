
Problem idea: we want to assign workers to orders over several days. The output is a days vector, where each day contains 
a 2D matrix: dayWorkerOrderHours[day][worker][order]

the value stored is the number of hours assigned to a worker for an order on that day

- use a greedy algorithm
- the algorithm gives priority to urgent orders first, then tries to assign the most suitable multi-skilled workers
- this is useful because a multi-skilled worker can cover several required skills for the same order minimizing the workers 
per order hence allowing for more workers to work on other orders simultaneously and can reduce completion time
- for example, if an order requires packing, quality inspection, and labeling, a worker who has all three skills can work 
on the order alone

baseline solution steps:

1. create the 3D vector: dayWorkerOrderHours[days][workers][orders] and initialize all values to 0

2. sort orders by: earliest deadline first and if deadlines are equal, higher priority first

3. for each order that is not completed: check if the order can still be completed before its deadline.

4. loop over the sorted orders and allocate the workers depending on wether the worker is suitable or no 
    so basically take or leav the worker
    a worker is a good candidate if:
   - the worker has the required skills
   - the worker still has available hours today
   - the worker is not already working on another order at the same time
perferable to check multi-skilled workers first

5. if one worker covers all required skills and the order only needs one worker then assign as many hours as possible

6. if the order requires teamwork choose the smallest possible team that satisfies:
   - all required skills are covered
   - number of workers is at least required_workers
   - each worker has available hours

7. split the remaining order hours between the selected workers
   a simple split is equal hours between workers and if workers have different efficiency rates greedily 
   choose the highest efficiency rates descendingly

8. update: worker used hours, order remaining hours, dayWorkerOrderHours[day][worker][order]

9. for each day decrement deadline_days_left

10. base cade: order completed if remaining_hours <= 0

11. solution valid if completion_time < original_deadline_days_left * 24

solution correct because:
1. checks the main constraints before assigning hours
it makes sure that:
2. worker is only assigned if they have the required skill
3. worker does not exceed daily working limits
4. orders are handled before their deadline by always choosing urgent orders first , allowing for all orders to be completed 
5. multi-skilled workers are preferred, reducing completion time 

how its limited because:
1. may fail to find a valid solution even if one exists, because it does not try all possibilities
2. does not minimize cost since a cheaper worker may be ignored if another worker has more skills
3. does not fully optimize completion time it only tries to finish urgent orders first
3. and the most important limitation since it could jeopardize the answer is it does not handle exact 
start and end times inside the day, only total daily assigned hours so it cannot fully guarantee 
that two tasks are not overlapping at a specific time

It's a good greedy solution however its not optimal a better future solution could use 
dp or backtracking to minimize total completion time and cost
